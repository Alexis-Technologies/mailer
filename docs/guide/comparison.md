# Compared with alternatives

@alexify/mailer is an email library in the place of the libraries below, built towards a
reliability layer none of them has. The table compares fourteen solutions in five directions: SMTP
clients (Nodemailer, emailjs), unified libraries over many providers (Upyo, unemail, sently), SMTP
for edge runtimes (worker-mailer, edge-mailer), a MIME builder (MIMEText) and the official SDKs of
the providers (Resend, SendGrid, Mailgun, Postmark, Mailtrap, Amazon SES). It follows the idea of
[Upyo's own comparison](https://upyo.org/why), with every feature in one table rather than a few
convenient libraries in a few convenient rows. @alexify/mailer itself is the first column, in teal
and, on a wide screen, pinned beside the features as the table scrolls, so every row reads against
it.

## What the table shows

- **None of the fourteen has a persistent queue, a local audit log and one model of delivery
  events.** unemail plans a queue. This is the gap @alexify/mailer is built for; see
  [Why @alexify/mailer?](/guide/why).
- **Breadth and correctness pull against each other.** sently covers SMS, push, WhatsApp and
  fourteen HTTP providers, but reading its code points to a bug in the canonicalization of the
  DKIM body and in SendGrid batches. Nodemailer and unemail are narrower and more precise.
- **Edge runtimes and SMTP barely mix.** It works only through `cloudflare:sockets` (sently,
  worker-mailer, edge-mailer), and port 25 is blocked in Workers. On the edge, an HTTP provider is
  the realistic option.
- **Idempotency is in 2 of the 14** (Resend and unemail). SES v2 has no `ClientToken`, so a retry
  after a timeout can send a message twice.

## How the table was made

- **From the code, not the README.** Every cell was decided by reading the source of a local
  clone of each project as of 2026-10-07.
- **The column of @alexify/mailer is this repository,** as of 2026-10-18. ✅ and ⚠️ are code that
  is here: the transport ported from upyo, with the upstream bugs fixed since, and what 1.1 took
  from nodemailer, unemail and sently, with their bugs fixed in the port. 🔜 is the reliability
  layer of [the plan](/guide/why#the-plan), designed but with no code yet. Its gaps are shown as
  such: no edge runtime, streaming only over SMTP and sendmail, and scheduling only where the
  provider schedules.
- **Defects were not reproduced,** except in emailjs, which was run against fake SMTP servers. A
  cell that names a bug is a finding from reading the code; reproduce it before relying on it.
- **The runtimes of the others were not run.** Their Deno, Bun and Workers support is inferred
  from imports, `exports` maps and CI configurations. The suites of @alexify/mailer run on Bun and
  Deno in its own CI.
- **The clones are shallow** (one commit), so the history, the number of maintainers and the pace
  of releases are not taken from git. Test cases were counted with a regular expression.
- **Amazon SES** means the newest SES client of the AWS SDK for JavaScript v3,
  `@aws-sdk/client-sesv2` 3.1147.0 (API 2019-09-27, 116 commands). The older `client-ses` (API
  2010-12-01, 71 commands) is still supported and is needed only for inbound rules. Its retry
  internals, the defaults of `NodeHttpHandler` and `AbortSignal` live in `@smithy` packages and
  were judged from their configuration types.
- **Size limits** of messages and attachments are set by the providers' documentation, not by the
  code of their SDKs, and are not in the table.
